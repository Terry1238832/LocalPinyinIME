# 前文语言模型

0.8.0 用一个新的字符 4 元语言模型（`resources/dictionary/context_zh.lm`）替换了原来基于约 20 万字自写语料的计数打分。它决定连续拼音的整句组合，以及输入新拼音时同音候选如何参考光标前的文字。

## 模型

- **平滑**：插值修正 Kneser-Ney，以回退形式存储；剪枝后的各阶重新归一化。
- **数据**：按权重计约 1,360 万字，来自项目原创与公有领域散文、Tatoeba 中文句子（CC BY 2.0 FR）、中文维基新闻（CC BY 2.5）、Mozilla Common Voice 句子（CC0）、KdConv 与 CrossWOZ 对话（Apache-2.0，0.14.1 起），以及内置词库词语内部的字组合（不带句子边界）。来源、校验值与处理步骤见 `resources/dictionary/authoring/context_lm_sources.json`。
- **规模**：1–4 阶共 213 万条，17.1 MB。键为 32 位：1–2 阶精确，3–4 阶为指纹（未出现的 n 元误匹配约三千分之一）。文件按只读内存映射加载，所有进程共享同一份物理内存。
- **省略标点**：连续拼音常常省略逗号，因此每个字也可以按“新子句开头”打分（`P($|前文)·P(字|^)`，再加一个固定代价），两者取较大值。
- **个人学习**：选过的词组中的字组合在模型之上获得额外加分，所以学过一次“写诗”，整句“你想写诗”也会优先这样组合。
- **无前文的单个词**：保持词库频率顺序，只用句首模型分数的十分之一打破同频（例如“请”和“晴”同为 9000 时，“请”在前）。

权重（语言模型 0.7、词频 3.0、句尾 0.5、拆分音节 1800、省略标点代价 1000）只在开发集上调整，测试集只在最后测量一次。0.13.0 增加两项：四字及以上句子的句尾权重 1.0、每个切分 600，同样只在开发半集（留出集偶数行）上选定，测量见 [INPUT_FEATURES](INPUT_FEATURES.md#整句输入)。

## 测量

测试集与训练数据分开：项目原有的四组整句用例从未参与训练；Tatoeba 和 Common Voice 中按文本哈希每 40 行留出 1 行，生成 `tests/data/heldout_sentences.tsv`（整句）和 `tests/data/heldout_context.tsv`（已上屏前文 + 下一个词的拼音）。下表为测试半集，0.7.9 与 0.8.0 使用相同词库：

| 测试集 | 用例 | 0.7.9 首选 | 0.8.0 首选 | 0.7.9 前三 | 0.8.0 前三 |
| --- | ---: | ---: | ---: | ---: | ---: |
| typing_holdout | 138 | 66.7% | 81.2% | 83.3% | 84.8% |
| typing_fresh | 67 | 56.7% | 61.2% | 73.1% | 70.1% |
| typing_independent | 62 | 38.7% | 41.9% | 48.4% | 62.9% |
| scenario_replay_076 | 32 | 46.9% | 62.5% | 71.9% | 78.1% |
| 留出整句 | 2,082 | 30.1% | 56.0% | 42.3% | 68.4% |
| 逐词输入（有前文） | 10,466 | 71.3% | 85.7% | 86.5% | 94.7% |
| 逐词输入（去掉前文） | 10,466 | 70.2% | 73.5% | 84.8% | 88.5% |

前文带来的首选提升：0.7.9 为 1.1 个百分点，0.8.0 为 12.2 个百分点。留出整句的字错误率从 24.6% 降到 10.9%。

仍然存在的不足：typing_fresh 的前三和前九覆盖略有下降（73.1%→70.1%，77.6%→74.6%）；他/她、在/再等真正需要语境之外信息的同音词仍要手动选择；整句查询的中位耗时约增加 2 ms（9–16 ms → 11–18 ms）。留出用例的拼音由 pypinyin 自动标注，少数多音字标注可能不准确，对新旧版本影响相同。

## 口语对话语料（0.14.1）

0.14.1 之前的训练文本以新闻和书面句子为主，口语里的“咋、其实、啥”这类字词接续估得偏低，例如“这种又是 zalaide”首选“杂来的”。0.14.1 加入两份清华大学 CoAI 组公开的对话语料（Apache-2.0，固定在仓库提交上，见 `context_lm_sources.json`）：

- KdConv：电影、音乐、旅行话题的多轮闲聊，约 8.3 万句用于训练；
- CrossWOZ：订酒店、找餐馆、问景点、坐地铁打车的办事对话，约 9.7 万句用于训练。

两份各按权重 1 加入（与维基新闻相同）。对话语料大量重复固定说法（“谢谢你啊”“营业时间是什么”），所以对话测试集 `tests/data/heldout_dialogue_*.tsv` 只收训练文本里从未出现过的留出子句（整句 3,368 例、逐词 19,504 例）。即便如此，同一句式换个名字的句子仍在训练里，CrossWOZ 部分尤其如此，这一组的提升会高估真实收益；KdConv 闲聊部分更接近日常口语。

| 测试集 | 用例 | 不加对话 | 加对话（权重 1） |
| --- | ---: | ---: | ---: |
| 口语对话·整句（KdConv 部分） | 1,679 | 49.7% | 72.5% |
| 口语对话·整句（CrossWOZ 部分） | 1,689 | 41.0% | 88.0% |
| 口语对话·逐词 | 19,504 | 84.66% | 94.10% |
| 留出整句（Tatoeba、Common Voice） | 4,126 | 58.07% | 57.71% |
| 逐词输入·参考前文 | 20,626 | 86.05% | 85.95% |
| 逐词输入·无前文 | 20,626 | 77.99% | 77.96% |
| 新增用例 | 67 | 56.72% | 62.69% |
| 项目留出 | 138 | 81.16% | 79.71% |
| 独立用例 | 62 | 45.16% | 43.55% |
| 场景回放 | 32 | 62.50% | 62.50% |

另试了权重 3/1、3/3、6/3：KdConv 部分再高约 4 个百分点，但留出整句和逐词的下降加倍，所以取 1/1。书面句子（Tatoeba、Common Voice）略有下降，是口语统计分走了一部分概率的代价。查询耗时不变（整句 95 分位约 38 毫秒）。

## 重新生成

```powershell
python tools/fetch_context_corpus.py --work <工作目录> --write-eval tests/data --write-dialogue-eval tests/data
python tools/build_context_lm.py ...   # 完整参数见 context_lm_sources.json 的 build_command
```

需要 numpy、opencc，生成测试用例时还需要 pypinyin 和 jieba；这些只在生成数据时使用，不进入安装包。
